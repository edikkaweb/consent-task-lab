The distinction

Feedback is only the beginning.

Start with a service that never answers. The same optional offer sits behind both versions.

Why measure both? In the frozen campaign, all 80 unfinished baseline tasks still recorded a 16 ms Event Timing duration. Those are archived results, not readings from this view. See the measured results.

The expected result is Canvas trainer, then Walking shoe, with no extra products.

What this comparison shows — and what it measures

Click handler means the handler ran and updated its feedback. It is not a measured Event Timing duration or proof of a painted frame. One button invokes the waiting handler first, then the independent handler, on the same main thread. Both use one shared offer promise; this is not a benchmark between independent pages.

Correct result comes from a separate DOM check: exact product IDs, names and order, with hidden/style/layout checks. Its own reads add work. A match must occur within 1,500 ms and still be present at the observation checkpoint. The checkpoint can run late in a background tab. The products and offer can still change afterward; the recorded checkpoint remains fixed. A changed or obstructed visual presentation is not fully covered by this DOM assertion.

Optional offer comes from a real request to the local simulator: a response after a 600 ms server delay, a closed connection, or a response held pending. Acceptance starts one shared fetch; rejection starts none. A browser may make several network attempts after a connection is cut, even for that single fetch. A response may arrive before you filter. No delay is added to manufacture a difference.

This teaching companion uses fresh, in-memory choices and separate presentation code. It does not reproduce the campaign’s input spacing, saved-choice states, CPU slowdown or measuring instrument. Its observations are never added to the frozen 480 trials. Use the original lab for the original interface and saved preferences; read the verified results for the measured campaign.
